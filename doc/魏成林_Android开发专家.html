重点项目介绍

  1. 《360聚合打包SDK》： 开发+维护 7.5 年，是 Android 多渠道游戏 SDK 聚合平台，面向 360 独家代理游戏发行体系，将各渠道 SDK（360联运、oppo/vivo/小米/华为/荣耀、bilibili、UC、大臣 等 40+ 渠道）归一到统一「聚合SDK」，使 CP 一次接入即可全渠道发包。
    • 整合友盟/厂商推送、微信、引力引擎及 8 家广告插件等三方 SDK，按渠道差异化开关接入打包平台，规避厂商审核风险。
    • 主导 Python 自动化多渠道打包工具：apktool 反编译母包 → 按渠道注入 SDK/插件/运行参数 → smali 层改写 + aapt2 重生成 R 资源 → 回编译 → zipalign + v1/v2/v3 三重签名，支持多包名批量产出、并发打包与按 jar md5 的增量缓存，一个命令完成全渠道出包。
    • 重构渠道接入方式：由「手动拆解 AAR 再合并」改为 Android Studio 编译直接产出 dex，打包时直接 merge；并通过切 dex（split_dex）解决多三方 SDK 合并后的方法数超限（65535）问题。
    • 打包时直接复用渠道 SDK 编译产物 dex、跳过解包/合并步骤，打包速度提升约 3 倍。
    • 修复 R 文件 ID 在重新打包后错乱问题：针对重编译后三方 AAR 资源 id 错乱的问题，实现 smali 字节码层面的 R 资源 id 自动重映射——单次遍历反编译目录树收集三方 `R$*.smali` 与主包 R 建立 id 映射，逐行替换并做一致性校验；针对 `declare-styleable` 中 attr 引用同步改写（如 ConstraintLayout 控件错位），并用「映射预构建 + 单次正则批量替换」优化，避免逐行全量 replace 的性能开销。
  2. 《360官方联运手游SDK》： 开发+维护 7.5 年，面向 360 游戏中心第三方 CP 的官方联运 SDK，提供登录、支付、社交、游戏支持等一站式能力。
    • 采用插件化架构：CP 侧仅集成轻量 sdk_in 宿主库，主体 UI 与业务逻辑封装在独立插件 APK（登录/支付/悬浮球/礼包/加速等）中，运行时由 ApkPluggingManager 动态加载，实现 SDK 不发版即可热更新。
    • 配套交付 CP 自检工具（apkchecker.jar）、本地打包脚本与完整发版流程。
  3. 《坦克世界助手》《战舰世界助手》： 坦克世界和战舰世界这俩大型PC游戏的官方app，从0到1实现安卓版和鸿蒙版
  4. 《鸿蒙手游SDK》： 360独代游戏上线鸿蒙渠道使用的SDK，从0到1开发实现
  5. 《360手机卫士》《360手机助手》： 日常开发+维护 1 年有余。主导 AI 去插件化重构：原为 360 RePlugin 插件化框架，一个主程承载约 30 个插件 APK，开发维护成本极高；使用 Claude Code 将各插件代码自动化合并回主程，平均 3 天合并一个插件，显著降低工程复杂度与维护成本
  6. 《Android 快速开发框架（BaseMyProject）》： 自己维护多年的开源快速开发框架，可快速从 0 到 1 完成 App 开发。GitHub：chenglin198751/BaseMyProject
